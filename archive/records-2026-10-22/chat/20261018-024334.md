That 429 is not your project's daily limit. The consumer in the error, project number 32555940559, is the gcloud tool's own shared Google project, which it uses when no quota project is set. Everyone's requests count against it, so it is often exhausted. Your trial project's number is 809363853518, and its daily count is untouched.

Fix: bill the API call to your own project with `--billing-project`. Run the first one, then the second:

```
gcloud quotas preferences create --project=project-5b3deb12-80e9-4df1-90b --billing-project=project-5b3deb12-80e9-4df1-90b --service=compute.googleapis.com --quota-id=CPUS-ALL-REGIONS-per-project --preferred-value=48 --email=owenchen07dev@gmail.com --justification="CPU-bound self-play workers for a board-game AI: 4-vCPU t2d VMs under steady 24/7 load"

gcloud quotas preferences create --project=project-5b3deb12-80e9-4df1-90b --billing-project=project-5b3deb12-80e9-4df1-90b --service=compute.googleapis.com --quota-id=T2D-CPUS-per-project-region --dimensions=region=us-east1 --preferred-value=48 --email=owenchen07dev@gmail.com --justification="Same self-play workers, T2D family in us-east1"
```

If it answers with a permission error about serviceusage, your account needs the Service Usage Consumer role on the project, which an owner has by default, so that is unlikely. If it still says the trial cannot change quotas, the upgrade has not propagated yet. Wait a few minutes and retry.

Checking later also needs the flag:
```
gcloud quotas preferences list --project=project-5b3deb12-80e9-4df1-90b --billing-project=project-5b3deb12-80e9-4df1-90b
```
