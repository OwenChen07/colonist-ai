Quick note: Kaggle blocks page fetching, so I only got the write-up's opening and the comments via search, not the full text. Here's what it says and what transfers.

**What it is:** Chris Deotte won a tabular competition (predict smartphone addiction, AUC 0.972) almost entirely with coding agents. Phase 1: one agent, data plus goal, 4 days unattended, built a 380-model ensemble, top 10. Phase 2: two agents racing on the same target (best single neural net, best single XGBoost), with a shared knowledge database, and he passed the leader's tips to the laggard. Phases 3-4: a swarm of agents, about 150 LLMs to pick from.

**The ML itself doesn't transfer.** Huge ensembles of tabular models are the wrong tool for a search bot; the cheap version of ensembling is weight averaging, which E12 already does.

**The orchestration ideas do, and we have half of them:**
- Shared knowledge database: we have experiments.md, journal.md and progress notes. Missing: a short cross-workstream "findings" file that every worker reads first and appends to (e.g. live-loss's "fewer cities, 22% wins" should reach training directly, not via me).
- Two agents racing with tip-sharing: possible now with 3 slots on Max, but only on a target that's cheap to score. Our experiments cost GPU hours and one PC, so a race would just queue. The one fit: after E16, race two workers on offline value error with the same budget.
- Long unattended runs: his agent ran 4 days; ours get 50 minutes. The controller-script pattern (e11b, e16) already covers long jobs. I'd not raise the cap.
- Goal, not recipe: he gives data and a goal, then adds clues. My briefs are more prescriptive. Worth loosening for training.

**Recommend:** add the findings file now (small), and a value-error race after E16. Want me to queue those? If you paste the full write-up text, I'll check phases 3-4 for more.
