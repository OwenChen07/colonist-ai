Yes. Upgrade first: Google's docs state plainly that a Free Trial billing account cannot request quota changes, so requests before the upgrade would be refused. Then run these from the coordinator, where the trial login already exists, or from any machine logged in as the trial account.

**Step 1, confirm the quota IDs** (the two IDs below are the documented naming pattern, but this check costs no request):
```
gcloud services enable cloudquotas.googleapis.com --project=project-5b3deb12-80e9-4df1-90b
gcloud quotas info list --service=compute.googleapis.com --project=project-5b3deb12-80e9-4df1-90b | grep -iE 'quotaId.*(ALL-REGIONS|T2D)'
```
If `gcloud quotas` is unknown, run `gcloud components install beta` and use `gcloud beta quotas` instead.

**Step 2, the two requests**, global CPUs first since it is the one that binds:
```
gcloud quotas preferences create --project=project-5b3deb12-80e9-4df1-90b --service=compute.googleapis.com --quota-id=CPUS-ALL-REGIONS-per-project --preferred-value=48 --email=owenchen07dev@gmail.com --justification="CPU-bound self-play workers for a board-game AI: 4-vCPU t2d VMs under steady 24/7 load"

gcloud quotas preferences create --project=project-5b3deb12-80e9-4df1-90b --service=compute.googleapis.com --quota-id=T2D-CPUS-per-project-region --dimensions=region=us-east1 --preferred-value=48 --email=owenchen07dev@gmail.com --justification="Same self-play workers, T2D family in us-east1"
```

**Step 3, check status later:**
```
gcloud quotas preferences list --project=project-5b3deb12-80e9-4df1-90b
```

Two notes. If the ID check in step 1 prints a different spelling, use that spelling in step 2. And the two-a-day limit is not in the docs, so I cannot confirm it, but these two are the only ones needed: if you get just one, make it the global one, since T2D in us-east1 is already 24 and allows three more VMs on its own.
