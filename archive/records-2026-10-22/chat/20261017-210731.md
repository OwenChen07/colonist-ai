Not from here, for two reasons: the service account you created only has the Compute Instance Admin role (quota changes need the Cloud Quotas Admin role), and the workers' allowed commands cover `gcloud compute` only. Both are deliberate limits, and I'd leave them.

From your Mac, with your own login, it's three commands:

```
gcloud services enable cloudquotas.googleapis.com --project colonist-ai-selfplay

gcloud beta quotas preferences create --service=compute.googleapis.com --project=colonist-ai-selfplay --quota-id=CPUS-ALL-REGIONS-per-project --preferred-value=96 --preference-id=cpus-all-regions-96 --justification="self-play compute for an ML research project"

gcloud beta quotas preferences create --service=compute.googleapis.com --project=colonist-ai-selfplay --quota-id=T2D-CPUS-per-project-region --dimensions=region=us-east1 --preferred-value=64 --preference-id=t2d-us-east1-64 --justification="self-play compute for an ML research project"
```

If either quota ID is rejected, list the exact names with:
```
gcloud beta quotas info list --service=compute.googleapis.com --project=colonist-ai-selfplay --format="value(quotaId)" | grep -iE "ALL-REGIONS|T2D"
```
and swap it in. If it asks for `--email`, add yours.

Check status later with `gcloud beta quotas preferences list --project=colonist-ai-selfplay`; approved ones show the new value in `regions describe us-east1`. Small requests like these usually go through within minutes to a few hours. Efficiency is told to watch the quota and scale once it moves.

Sources: [Manage quotas using the gcloud CLI](https://docs.cloud.google.com/docs/quotas/gcloud-cli-examples), [quotas preferences create reference](https://docs.cloud.google.com/sdk/gcloud/reference/beta/quotas/preferences/create)
