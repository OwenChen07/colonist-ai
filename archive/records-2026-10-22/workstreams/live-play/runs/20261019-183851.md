bot8's first game stopped because its VM ran out of memory, not mainly because of CPU. Bot VM 2 has 2 cores and 4 GB, was running 3 browsers and 3 bots, and was swapping hard. The browser page froze for 7 s, longer than the 4 s the bot waits for a move to be confirmed. bot8's search also ran at about 180 simulations a second, against about 1,000 for bot3 and bot4 on the same VM.
Landed (800 tests): the bot now waits 5 s before resending a move and 5 s more before stopping. It goes live with the next sync and safe restarts. This only hardens the bot; it does not fix the memory.
Cheapest fix with no new VM: run bot8 in place of bot4 on VM 2, which keeps two accounts per VM. Fewer simulations would not help, because the memory goes to the browser. VM 1 has no room either.
